# KPulse — دليل التشغيل والنشر

تطبيق واحد بملف HTML واحد (`index.html`)، بدون أي عملية بناء (build). يعتمد على:
- **Supabase** لقاعدة البيانات (جدولا `entries` و `constraints`) وتسجيل الدخول.
- **Vercel** لاستضافة الموقع مجانًا.

بما أنك لا تملك أي من الحسابات الثلاثة بعد، اتبع الخطوات بالترتيب. كل خطوة تتطلب حسابًا مجانيًا فقط (بريد إلكتروني).

---

## 1) إنشاء مشروع Supabase (قاعدة البيانات + تسجيل الدخول)

1. اذهب إلى https://supabase.com وأنشئ حسابًا مجانيًا (يمكنك التسجيل عبر GitHub لاحقًا لتسهيل الأمور، أو ببريدك الإلكتروني).
2. من لوحة التحكم اضغط **New project**.
   - اختر اسمًا مثل `kpulse`.
   - اختر كلمة مرور لقاعدة البيانات (احفظها في مكان آمن، لن نحتاجها في الكود).
   - اختر أقرب منطقة (Region) لك.
   - اضغط **Create new project** وانتظر دقيقة أو دقيقتين حتى يجهز.
3. من القائمة الجانبية اذهب إلى **SQL Editor** → **New query**.
   - افتح ملف [schema.sql](schema.sql) الموجود في هذا المجلد، انسخ محتواه بالكامل، الصقه في المحرر، ثم اضغط **Run**.
   - هذا ينشئ الجدولين، يفعّل الحماية (Row Level Security)، ويفعّل التحديث اللحظي (Realtime).
4. (اختياري لكن يسهّل التجربة) اذهب إلى **Authentication → Providers → Email**، وأوقف خيار **Confirm email** حتى يستطيع المستخدمون تسجيل الدخول مباشرة بعد إنشاء الحساب دون تأكيد بريد إلكتروني. إن تركته مفعّلاً، سيحتاج كل مستخدم جديد للنقر على رابط التأكيد الذي يصله بالبريد قبل أول تسجيل دخول.
5. اذهب إلى **Project Settings (⚙) → API**. انسخ القيمتين التاليتين:
   - **Project URL**
   - **anon public** key (المفتاح العام — آمن استخدامه داخل كود الواجهة الأمامية).
6. افتح [index.html](index.html) وابحث عن هذا السطر بالقرب من بداية الـ `<script>`:
   ```js
   const SUPABASE_URL = "YOUR_SUPABASE_URL";
   const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
   ```
   استبدل القيمتين بما نسخته من الخطوة السابقة، واحفظ الملف.

بعد هذه الخطوة، افتح `index.html` مباشرة في المتصفح (بدون سيرفر) — يجب أن تظهر شاشة تسجيل الدخول وتعمل: أنشئ حسابًا (Create Account) بأي بريد إلكتروني وكلمة مرور، ثم جرّب إضافة تقرير يومي أو قيد.

---

## 2) رفع الكود إلى GitHub

Vercel يحتاج مستودع GitHub ليربطه بالنشر التلقائي.

1. أنشئ حسابًا مجانيًا على https://github.com إن لم يكن لديك.
2. من صفحة GitHub الرئيسية اضغط **New repository**، سمّه `kpulse-app`، اجعله Public أو Private، لا تضف أي ملفات تهيئة تلقائية، ثم **Create repository**.
3. في هذا المجلد على جهازك، شغّل الأوامر التالية (استبدل الرابط برابط المستودع الذي أنشأته):
   ```bash
   git add -A
   git commit -m "KPulse: Supabase auth + database wired in"
   git branch -M main
   git remote add origin https://github.com/YOUR_USERNAME/kpulse-app.git
   git push -u origin main
   ```
   (سيُطلب منك تسجيل الدخول إلى GitHub في المتصفح أول مرة — هذا أمر طبيعي.)

---

## 3) النشر على Vercel

1. أنشئ حسابًا مجانيًا على https://vercel.com — الأسهل هو الضغط على **Continue with GitHub** لربط الحسابين مباشرة.
2. من لوحة Vercel اضغط **Add New → Project**.
3. اختر مستودع `kpulse-app` من القائمة واضغط **Import**.
4. لا حاجة لأي إعدادات بناء (Build Command / Output Directory) — الموقع HTML ثابت. اضغط **Deploy** مباشرة.
5. بعد دقيقة تقريبًا سيعطيك Vercel رابطًا مباشرًا مثل `kpulse-app.vercel.app` — هذا هو رابط تطبيقك المنشور، ويعمل لأي شخص من فريقك يفتحه ويسجّل حسابًا.

كل تحديث تدفعه لاحقًا إلى فرع `main` على GitHub (`git push`) سينشر تلقائيًا نسخة جديدة على Vercel.

---

## ملاحظات مهمة

- **البيانات مشتركة بين كل من يسجّل دخول**: أي مستخدم مسجَّل يرى كل التقارير والقيود ويضيف عليها (كما في التصميم الأصلي "Shared with your team")، والتحديثات تظهر فورًا لدى الجميع (Realtime) بدون الحاجة لتحديث الصفحة.
- **الصور**: تُخزَّن مصغّرة كنص Base64 داخل قاعدة البيانات مباشرة — مناسب للنموذج الأولي هذا. إذا كبر عدد الصور مستقبلًا، الخطوة التالية الطبيعية هي استخدام **Supabase Storage** بدل تخزينها كنص.
- **الخطة المجانية لـ Supabase** تكفي هذا النموذج بسهولة (500 ميغابايت قاعدة بيانات، مستخدمين غير محدودين تقريبًا للاستخدام الخفيف).
- **الخطة المجانية لـ Vercel** تكفي أيضًا لموقع ثابت كهذا دون أي تكلفة.
